# 甲方图文功能手册（实机走查 → HTML）

面向「给甲方看」的交付：实地登录前后台 → 梳理功能 → 截图 → 单文件 HTML 手册（配图）。

## 何时启用

- 用户提供前台/后台 URL + 账号，要求整理功能、做图文教程/手册
- 关键词：功能使用简介、图文并茂、甲方、验收文档、操作手册、产品说明书

## 输入清单（缺则先问）

1. 用户端 URL、管理端 URL
2. 两端账号密码
3. 输出语言（默认中文）
4. 演示链接是否对外展示：默认**可写真实地址**；若用户要求隐藏测试链，改为「联系 TG/客服获取演示」并写明联系方式
5. 产品品牌名（从页面 title / logo 确认，勿瞎编）

## 工作流（必须按序）

### 1. 准备目录

```
{workspace}/docs-{product}/
  screenshots/
  {Brand}-功能使用手册.html
```

截图写入可写目录（本机常见：`C:/Users/<user>/...` 或工作区 `docs-*/screenshots/`）。Playwright 相对路径常落到用户主目录，事后拷贝进手册同级 `screenshots/`。

### 2. 实机登录

- 用浏览器工具访问；**H5 用手机视口**（如 390×844），**后台用桌面视口**（如 1440×900）
- 遇验证码：
  - 先尝试识别（SVG base64 可读字符；小图可截取后用 Read 看图）
  - 识别不了则把验证码图报给用户填写，**不要卡住整单**
- 登录成功后再系统走查；勿在未登录态假装功能完整

### 3. 功能地图（优先程序化）

- H5（uni-app）：读 `window.__uniRoutes` 得到页面清单
- 后台（Vue）：读 `$router.getRoutes()` / 侧栏菜单文本
- 整理为：用户端能力列表 + 后台一级/二级模块树
- 对照表字段：`用户端能力 | 前台入口 | 后台模块 | 运营要点`

### 4. 批量截图（代表页优先）

**用户端至少覆盖：**

| 优先级 | 页面 |
|--------|------|
| 必截 | 首页、行情、现货、合约/期货、资产 |
| 高优 | 充值、提现、闪兑/兑换、理财、跟单、C2C、邀请、活动/福利、个人中心/更多 |
| 选截 | 设置、盈亏分析、期权、客服等差异化模块 |

**管理端至少覆盖：**

| 优先级 | 模块 |
|--------|------|
| 必截 | 仪表盘、用户/会员、充值、提现、现货订单、合约订单 |
| 高优 | KYC、钱包/流水、C2C、理财、跟单、交易对/币种、公告、客服、活动、系统/权限 |
| 选截 | 监控日志、代理返佣细项、期权/盲盒等 niche 配置 |

命名建议：`h5-01-home.png`、`admin-01-dashboard.png`（序号 + 英文短名）。

### 5. 写 HTML 手册（交付物）

- **一个 HTML + 同级 screenshots/**，浏览器本地可打开
- 受众：甲方（演示、培训、验收），不是开发 README
- 结构见 [manual-template.md](manual-template.md)
- 视觉：大气、品牌优先；遵守用户前端设计规则（避免紫白渐变、奶油衬线、报纸风等 AI 烂大街套路）
- 正文中文；步骤用「01 / 02 / 03」可执行说明，不要空话

### 6. 敏感信息处理

- 手册里**不要写真实密码**
- 若用户要求去掉测试链接：删除所有环境 URL，改为指定客服渠道（如 `@daqi56`）
- 勿保留「文档与截图说明 / 截图目录路径」等对甲方无用的元说明（除非用户要）

### 7. 交付话术

简短告知：

1. 手册路径  
2. 覆盖了哪些端/模块  
3. 如何打开（浏览器打开 HTML，保持 screenshots 同级）

可另附「四张前端代表图」路径：首页、现货、合约、资产（用户常会再要）。

## 质量门禁

- [ ] 两端均已实机登录并截到登录后界面
- [ ] 有前后台功能对照表
- [ ] 有关键操作步骤（充提、交易、审核至少各一条链路）
- [ ] 截图与正文一一对应，无裂图
- [ ] 无密码；链接策略符合用户最新要求
- [ ] 无「本文档仅供内部」类冗长免责堆砌（一句投资风险提示可保留）

## 反例

- 只根据公开页猜功能、不登录后台
- 交 Markdown 长文却几乎无图
- 做成开发接口文档口吻
- 把 localhost / 测试账号密码印在甲方稿上
