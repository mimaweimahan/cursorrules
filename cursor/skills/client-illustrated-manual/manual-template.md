# 甲方手册 HTML 结构模板

生成单页 HTML 时按此骨架组织；样式自拟，保持大气、品牌优先。

## 页面区块顺序

1. **Hero**：品牌名（最大视觉）+ 一句话定位 + 元信息 chips（演示获取方式 / 版本 / 日期）+ 锚点 CTA  
2. **Sticky TOC**：平台总览 / 用户端 / 交易 / 资产 / 增长 / 管理后台 / 运营流程 / 对照表  
3. **平台总览**：能力数字摘要 +「获取演示」或入口说明 + 建议演示顺序  
4. **用户端**：登录安全 → 配手机框截图  
5. **交易能力**：闪兑 / 现货 / 合约 / 期权（有则写）— 左步骤右截图  
6. **资产与出入金**：总览、充提划转、C2C  
7. **增长玩法**：理财、跟单、邀请、新人福利  
8. **管理后台全景**：仪表盘大图 + 模块卡片网格  
9. **运营场景**：A 会员 KYC → B 充提审核 → C 订单风控 → D C2C/理财/跟单/活动 → E 币对内容客服系统（配后台截图墙）  
10. **前后台对照表**（表格）  
11. **验收建议清单**（必测 / 选测）  
12. **Footer**：品牌 + 演示获取方式 + 一句非投资建议

## 文案语气

- 对甲方：清晰、可演示、可验收  
- 步骤动词开头：打开 / 选择 / 填写 / 提交 / 审核  
- 避免：源代码路径、API、技术栈炫耀（除非甲方要）

## 截图展示约定

- H5：`.shot.phone` 窄框，可多列 `phone-row`  
- 后台：`.shot.desk` 宽图；两列 `admin-gallery`  
- 每图必有一句 `shot-caption`

## 对照表示例行

| 用户端能力 | 前台入口 | 后台模块 | 运营要点 |
|------------|----------|----------|----------|
| 充值 / 提现 | Assets · Recharge · Withdraw | 财务管理：充值 / 提币审核 / 钱包 | 到账确认、提现风控 |
| 现货交易 | Spots | 现货订单 · 现货设置 | 交易对开关、手续费 |

## 演示链接策略

**默认**：可写真实用户端/管理端 URL。  

**隐藏测试环境时**（用户明确要求）：

```html
<li>演示地址与账号不对外公开。</li>
<li>联系 Telegram 客服：<a href="https://t.me/xxxx">@xxxx</a></li>
<li>客服提供最新演示链接与测试账号。</li>
```

Hero chips 同步改为「演示环境 · 联系客服」「TG 客服 · @xxxx」。
